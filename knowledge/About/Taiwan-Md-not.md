# Taiwan.md 不是什麼：一份知識庫先把自己的邊界說清楚

你打開 Taiwan.md 的一篇文章，看到的不是一個把台灣所有資料倒進 Markdown 的倉庫。頁面裡的句子有腳註，腳註連到具體文章頁；頁面右下角有 `.md` 按鈕，原始文字可以被拿出來檢查；文章最後還留著貢獻與修訂的入口。[^1] 這些細節其實都在回答同一個問題：**Taiwan.md 到底把自己當成什麼？** 既有 About 文章也把它描述成以 Markdown 保存、能被人與 AI 讀取的開源台灣知識庫，而不是封閉的編輯產品。[^7]

最準確的答案，要從反方向說起。Taiwan.md 不是什麼，不只是宣傳用的否定句，而是一份使用說明。它把「不做什麼」寫在檯面上，讀者才不必猜測一篇文章為什麼選了這個人、刪掉那個數字，又為什麼願意留下可被改正的錯誤。

## 它不是百科全書

![2007 年台灣維基人與 Wikimedia 創辦人 Jimmy Wales 的合照；這張照片呈現共同編輯社群，而不是單一作者的作品。](https://commons.wikimedia.org/wiki/Special:FilePath/Taiwanese%20people%20Wikipedians.jpg?width=1200)
_2007 年台灣維基人與 Jimmy Wales 的合照。攝影：Ellery；圖片授權：CC BY-SA 3.0。圖片頁：[Wikimedia Commons](https://commons.wikimedia.org/wiki/File:Taiwanese_people_Wikipedians.jpg)。_

Taiwan.md 不打算把每個台灣名詞都補成一個條目，也不承諾在每個爭議上給出最後答案。這一點和維基百科「不是什麼」的自我說明有一個重要的相似處：一個知識計畫必須知道，真實、實用或有趣，不會自動讓一段材料適合放進它的正文。百科的規範因此排除原創研究、廣告與自我宣傳，並要求內容可驗證。[^2]

但 Taiwan.md 的工作不是把百科條目再做一次。它做的是比較小、也比較有選擇的事：從一個具體的人、一個物件或一個場景進入，挑出能讓讀者理解「所以呢」的材料，再把它寫成一篇可以被追問的故事。這就是策展的代價——**一篇文章一定會留下很多東西在文章外**。

| 讀者以為自己要找的 | Taiwan.md 實際先處理的問題 |
| --- | --- |
| 一個名詞的完整資料 | 哪個具體細節能改變讀者的理解 |
| 所有可能的觀點 | 哪些重要觀點有可靠來源，彼此如何衝突 |
| 一份永遠不變的答案 | 一份目前可查證、也能被修訂的版本 |

這不代表 Taiwan.md 可以任意挑自己喜歡的故事。選擇仍然要受到來源、脈絡與反例約束。維基百科的中立觀點規範要求公平、按比例呈現可靠來源中的重要觀點；Taiwan.md 可以採取台灣人的主體位置，卻不能把「我有立場」當成免除查證的通行證。[^3]

## 它不是旅遊指南

旅遊指南回答的是「下一站去哪裡、怎麼到、幾點開門」。Taiwan.md 偶爾會寫一座市場、一棟建築或一道食物，卻不把台灣切成可以快速消費的景點卡片。它更在意一個地方如何被使用、被記憶，又如何在不同的人手裡變成不一樣的台灣。

因此，一篇寫夜市的文章不必只列出十家必吃攤位；它可以追問，為什麼油煙、攤車、排隊與熟客的叫法，會共同構成一種城市秩序。一篇寫老屋的文章也不必停在建成年份；它可以讓屋主、鄰居、修復者或租客出場，讓建築從一張外觀照片變成有人在裡面生活的物件。

這種寫法不保證每個讀者都能立刻得到一條路線。它提供的是另一種實用性：讀者離開頁面後，知道自己下次走進一個地方時，可以多看哪一層。**Taiwan.md 想留下的不是「去過了」的證明，而是「看懂一點了」的可能。**

![桃園市立圖書館總館的室內空間；書架、閱覽桌與通道共同構成一個可被使用的公共知識場所。](https://commons.wikimedia.org/wiki/Special:FilePath/Interior%20of%20Taoyuan%20Main%20Public%20Library%202022-12-22.jpg?width=1600)
_桃園市立圖書館總館內部。攝影：Foxy1219，2022；圖片授權：CC BY-SA 4.0。圖片頁：[Wikimedia Commons](https://commons.wikimedia.org/wiki/File:Interior_of_Taoyuan_Main_Public_Library_2022-12-22.jpg)。_

這張圖不是要替「台灣有漂亮圖書館」這個結論背書。它比較適合提醒讀者：知識不是只有被收藏的內容，也包括誰能走進來、怎麼找到它、能不能在使用後留下修正。Taiwan.md 把文章放在公開 repo 裡，想保留的正是這種可進入、可檢查、可接續的關係。

## 它不是宣傳稿

台灣值得被好好介紹，並不等於每一篇文章都要替台灣鼓掌。宣傳稿把複雜性整理成可轉發的結論；策展文章則要把結論的成本也放在桌上。若一項文化成就伴隨勞動條件、資源分配或歷史爭議，這些不方便的部分不是文章的噪音，而是主題的一部分。

Taiwan.md 的主體性，指的是從台灣生活經驗出發，而不是預先規定讀者讀完必須感到驕傲。這一點也回應了 Taiwan.md 對「為什麼需要自己的知識庫」的說明：建立自己的版本，不等於把它宣布成唯一版本。[^8] 它可以明確寫「台灣」，也可以指出外部敘事漏掉了什麼；同時，它仍要把事實、來源與作者的判斷分開。這也是為什麼策展人筆記不應該冒充正文：筆記可以說明「我們為什麼選這個角度」，正文則要讓讀者自己檢查材料是否撐得住。

> **策展人筆記**：主體性不是把所有台灣經驗說成同一個聲音。它比較像是在資料已經有很多人替台灣命名之後，補上一個「住在這裡的人怎麼描述自己」的入口；入口打開以後，裡面仍然有分歧。

## 它不是 AI 自動販賣機

Taiwan.md 的內容可以由 AI 協助起草，但這句話不能被讀成「按一下就得到可信文章」。貢獻頁把流程說得很直白：AI 起草，等人補完；讀者可以用表單、寄件或 Fork & PR 提供材料。[^1] 人不是文章發布後才來按讚的人，而是把親身經驗、家族記憶與專業知識帶進查核環節的人。

這裡的差別不在於「有沒有使用 AI」，而在於**誰對最後一句話負責，以及讀者能不能沿著來源回去**。Taiwan.md 的文章產線把觀點、取材、寫作、查證、視覺與連結分成不同階段，目的正是避免搜尋結果一出現，就把它們排列成一篇看似完整的文章。[^4]

一個 AI 很容易寫出「台灣有深厚文化底蘊」；它比較難自己回答：是哪一個人？哪一年？哪一個物件？哪一個來源？Taiwan.md 對抗的正是這種可以換掉主詞、仍然成立的句子。沒有可核驗的錨點，漂亮的概括就只是聲音。

## 它不是一個只靠 Prompt 就能複製的網站

把 Taiwan.md 的規則貼給另一個 AI，確實可以讓它模仿幾個表面的習慣：使用 Markdown、加上腳註、寫一個「策展人筆記」。但真正難以複製的不是語法，而是長期累積的取捨：哪些主題已經有人寫過、哪些來源曾被查證推翻、哪一個地方需要先問當地人，而不是先找一個聽起來完整的摘要。

這也是為什麼一份 Prompt 不能取代一個公開 repo。Prompt 可以交代任務，Git 歷史才會留下修改；Prompt 可以要求「請查證」，具體來源頁才讓下一個人知道查證了什麼。Taiwan.md 的規範若只停在對話視窗裡，會隨著一次回答結束；當它被寫進檔案、Issue 與 PR，它才變成可被社群接手的工作方法。

## 它不是絕對中立，也不是任意偏見

Taiwan.md 不把自己包裝成沒有位置的攝影機。從台灣的語言、生活與歷史出發，本身就是一個位置。可是「有位置」和「可以隨意下判斷」之間，仍然隔著來源、比例與修辭的紀律。

維基百科的中立觀點政策把這條界線說得很清楚：文章不應該替某一方站台，而應該公平解釋重要的不同觀點；中立也不等於把所有說法平均分配，而是按可靠來源與實際重要性給予適當篇幅。這套原則近年的 Wikimedia 編輯討論仍持續被拿來檢視，顯示「中立」本身也需要公開辯論與修訂。[^3] [^9] Taiwan.md 不必複製百科的制度，但可以借用這個檢查問題：**我是在讓一個被忽略的觀點出現，還是在替一個沒有證據的主張找舞台？**

前者是策展，後者是偏見。前者會把來源、限制與反例交給讀者，後者只會把語氣加重。當文章的觀點需要靠「大家都知道」「毫無疑問」「世界第一」這些無法定位的話來維持時，通常表示材料還不夠。

這條界線也適用於「台灣人」這個詞。它不能被當成一個沒有差異的單數主詞。住在台北的人、返鄉照顧家人的人、在台灣工作的移工、原住民族部落裡使用自身語言的人，對同一個制度的記憶可能不同。若文章只把其中一種經驗寫成台灣的總聲音，文字即使沒有明顯錯誤，也可能在敘事上失真。

因此，Taiwan.md 的主體性不應該由一位作者獨佔。它需要地方讀者指出口音、家族成員補充另一段記憶，或專業工作者提醒一個看似簡單的數字其實有定義差異。共同編輯不是把所有聲音調成同一個音高，而是讓不同聲音有名字、有位置，也有可以回頭查的來源。

## 它不是只追求好看的網站

Taiwan.md 的 `.md` 不是品牌裝飾。它指向一個很實際的選擇：內容以純文字保存，能被 Git diff、閱讀器、搜尋引擎與 AI 爬蟲讀取。這個選擇也延伸到圖表；視覺化指南要求關鍵數字寫進正文，並以語意 HTML 或 SVG 保留資料表 fallback，而不是把資訊鎖在一張圖片裡。[^5]

所以「AI-friendly」不等於為機器犧牲人類讀者。它反而要求作者把標題、來源、數字與結論寫得更清楚：人可以看圖，機器可以讀資料表；人可以被一個場景吸引，機器仍然能找到那個場景的名稱與時間。能被讀取，不應該成為降低文章品質的理由。

GitHub 對開源軟體的說明，把透明、協作與去中心化視為核心；公開的工作可以被檢視、修改、測試與共同維護。[^6] Taiwan.md 把同樣的精神放到文化內容上，意味著「公開」不只代表免費閱讀，也代表讀者看得到檔案、來源和修改的痕跡。

## 它不是一次交稿後就完成

一篇文章上線，不代表它從此正確。人物可能補充了新作品，制度可能改變，地方名稱可能被當地人指出更精確的寫法。若文章只展示最後版本，讀者看不到知識如何被修正；若它保留腳註、Git 歷史與貢獻入口，錯誤至少有機會被定位。

這也是 Taiwan.md 為什麼需要校對者，而不只需要讀者。讀者可以說「我喜歡這篇」，校對者會再問一句：「這個數字從哪裡來？」兩者都重要，但後者把知識庫往前推了一步。貢獻頁提供的不是一個神祕的編輯室，而是表單、信箱、討論區與 GitHub PR 等不同深度的入口。[^1]

> **一個可用的判準**：如果你不同意文章的一句話，先不要只問它是不是符合你的立場；先點開它綁定的來源，看來源真的說了什麼，再把缺漏或更好的版本送回來。

## 所以，Taiwan.md 是什麼？

它是一個有選擇的、可追溯的、允許被修正的台灣知識庫。這個定義故意不夠宏大：它沒有宣稱收納全部台灣，也沒有宣稱替台灣人發言，更沒有宣稱 AI 生成的每一句話都會自動變真。

它比較像一張公開的工作桌。桌上有材料、有剪裁留下的痕跡、有一盞照著來源的燈，也有一個空位，等下一個知道得更清楚的人坐下來。**Taiwan.md 不是把邊界藏起來才顯得完整；它把邊界寫出來，才讓人知道可以從哪裡開始參與。**

如果你發現一個地名寫錯、一段家族記憶缺了另一個人的聲音，或是一個腳註其實只連到搜尋頁，請把它指出來。你不必先成為作者；在 Taiwan.md，能讓一篇文章更可追溯，本身就是一種寫作。
