# 封面圖與內文視覺健檢（2026-11-19）

## 〇、一句話結論

1,189 篇中文文章，有封面的 277 篇（23.3%），沒有的 912 篇；讀者實際點進來的文章裡，四次點擊有三次落在沒有封面的那一批。沒有封面的文章有 729 篇連內文圖、資訊模組、嵌入影片都沒有，整頁只有字。能補的量比想像多：133 篇內文已經放了 Wikimedia 的圖，另外 184 篇在中文維基有同名條目、主圖是比例合適的自由授權照片。估計可以把封面覆蓋率從 23% 拉到 51% 到 57%，補不到的那一半主要是抽象議題與找不到授權肖像的人物。第一批補了 33 篇（附錄 A），過程中量到一個擋路的東西：全站有 90 篇文章只要被 commit 碰到，正文就會被格式化工具整理一次，譯本跟著要重翻（§九）。

## 一、怎麼量的

逐篇資料來自既有的普查儀器 `scripts/tools/article-census.py`（規則住在 `scripts/tools/lib/article_health/census.py`），沒有另寫掃描器。這次只在儀器上補了三個欄位：授權三欄分開記、模組依種類計數、資料類模組數。逐篇明細在 [`reports/cover-image-health/2026-11-19-articles.tsv`](cover-image-health/2026-11-19-articles.tsv)（1,189 列，依讀者點擊排序）。

範圍是 `knowledge/<分類>/*.md`，不含 `_` 開頭的 hub 與各語言譯本。

## 五、為什麼沒有封面

912 篇照處理成本由低到高分成三型（沿用 11/04 普查的 C1／C2／C3），最大的那一型再用中文維基探測往下拆。

### 5.1 內文有本地圖，只是沒設封面：5 篇

11/04 的普查找到 22 篇，當時用 `cover-promote.py` 升格了 16 篇。剩下的 5 篇是工具刻意跳過的：

| 文章              | 跳過原因                                       |
| ----------------- | ---------------------------------------------- |
| 彰化縣            | 圖說抄不到作者與授權，原 Commons 圖已下架      |
| 1935 新竹臺中地震 | 圖說抄不到作者或允收授權，也沒有「圖片來源」段 |
| 歡樂無法黨        | 同上                                           |
| 電網韌性          | 同上                                           |
| 李宗盛            | 圖的比例 0.67，當卡片會裁掉主體                |

這 5 篇要先回頭查那張內文圖的出處，查得到才升格。

### 5.2 內文有圖，但圖是外站熱連結：133 篇

圖是作者寫文章時已經挑好的，全部在 Wikimedia。要做的是核授權、下載進庫、去 EXIF、轉 WebP，再設成封面。這一型沒有找圖成本，是第一批的主體。要留意三件事：

- 內文第一張不一定代表這篇文章。例：〈Ceylan〉第一張是八德路街景，〈陳思宏〉第一張是員林地圖，〈韓國人在台灣〉第一張是高雄天際線。每篇要從它的幾張圖裡挑，挑不到就不設。
- 9/05 收卡片圖時有 15 篇收不進來，留了 `imageNote`：10 篇是 Commons 原檔已下架，2 篇圖與主題不符，1 篇只有 GFDL 授權，1 篇原圖太小，1 篇另有原因。內文的熱連結也會遇到同樣的狀況。
- 內文圖本身仍是熱連結。封面收進庫之後，內文那張是否一起換成本地檔，會動到正文，牽涉譯本要不要重翻，見 §七。

### 5.3 沒封面、內文也沒圖：774 篇

這一型要從頭找圖。用中文維基的 pageimages API 對全部 912 篇沒封面的文章做了一次低速探測（檔名當條目名、只收自由授權主圖），結果當成「有沒有現成候選」的估計，不是授權結論，落地前每一張都要再核一次。

| ---------------------------------------- | -----: | ----------------: | -------------------------------------------------------------------- |
| 有同名條目，主圖是比例合適的自由授權照片 |    184 |               140 | 有現成候選，核過授權與代表性就能落地                                 |
| 有同名條目，主圖是直幅（比例低於 0.75）  |     47 |                42 | 多半是肖像。能裁就裁（要註明），不能裁就另找                         |
| 有同名條目，主圖寬度不到 800             |    112 |                89 | 多半是低解析度肖像。要到 Commons 分類頁找同一個人的其他圖            |
| 有同名條目，主圖是標誌、地圖或向量圖     |     28 |                23 | 不適合當封面，要另找                                                 |

依題材看沒封面的原因：

- **人物（237 篇沒封面）**：218 篇有維基條目，但主圖可直接用的只有 37 篇。44 篇是直幅、83 篇太小、53 篇沒有自由授權圖、19 篇沒有條目（網路創作者、新興樂團、候選人）。這一類會留下最多「找不到授權圖」。在世人物只用授權清楚的肖像，找不到就留空。
- **抽象議題（Society、Economy、Politics、Technology、Lifestyle 共 286 篇沒封面）**：204 篇沒有同名條目，例如〈台灣的道德課去哪了〉〈來來來怎麼樣怎麼樣〉〈議員制度〉。可以用的是「場景圖」：立法院議場、投票所、補習街、KTV 招牌。要逐篇判斷那張圖是不是真的代表這篇，不能只是有圖。
- **有實體對象的題材（Food、Geography、Nature、History、Culture 共 320 篇沒封面）**：102 篇有現成候選，是 C3 裡最好補的。食物、地點、物種、建築在 Commons 幾乎都有照片。
- **藝術與音樂（64 篇沒封面）**：作品本身多半有著作權，能用的是人物肖像、展場外觀、表演現場的自由授權照片，候選只有 9 篇。

## 七、既有流程與已知的坑

補圖走既有工具，不另造：

- **落地**：`python3 scripts/tools/cover-ingest.py --manifest <清單> --apply`（第一批新增）。照清單對 Commons API 再核一次授權與作者，自己下載後交給 `image-ingest.mjs` 嗅探檔頭、去 EXIF 與 GPS、轉 WebP、壓到 600KB 以內，存 `public/article-images/<分類>/`，再寫 frontmatter 四欄。
- **下載來源（第一批實測後更正）**：Wikimedia 現在對原檔與 `Special:FilePath` 的程式下載一律回 429，只放行標準寬度的縮圖（960、1280、1920、3840 像素回 200，2400 回 400）。`image-ingest.mjs` 直接吃 Commons 檔案頁網址會卡死在重試裡。`cover-ingest.py` 改抓不超過原圖寬度的最大標準寬度（最多 1920），被限流時最長等四分鐘。
- **比例**：封面當卡片用，收 0.75 到 2.5（`cover-promote.py` 的範圍）；`image-ingest` 的 hero 檢查更窄（0.9 到 2.0），落在兩者之間的會印警告。文章頁內文不裁切，image-health 收 0.4 到 3.5。
- **授權**：卡片圖只收 CC BY、CC BY-SA、CC0、公有領域，以及 9/17 起納入的政府資料開放授權（OGDL-Taiwan-1.0，待決佇列 #50 已到期執行）。只有 GFDL 的不收，合理使用的不收。用 Commons API 的 `extmetadata` 查，一次可查五十個檔名。中文維基本地上傳的圖不等於 Commons 授權，要另外看。
- **限流**：Wikimedia 連續請求會回 429。這次探測每批五十個條目、間隔 1.2 秒，19 批裡有一批連撞兩次，等待後重試通過。圖檔下載每張間隔 8 秒，第一批五十多張沒有再撞。
- **封面必填**：image-health 在 rewrite-stage-4 把「沒有封面」當 HARD，在 ci-deploy 與 pre-commit 是 WARN。frontmatter 有授權欄位卻沒有 `image` 會被擋。
- **同一張圖不重複**：image-health 會擋同一篇裡同一張圖出現兩次。模板端在正文已有同一張圖時，文章頂部會讓位（`heroImageInBody`），原本只比對路徑，封面是本地檔、內文是同一張圖的熱連結時認不出來，同一張圖會在開頭連出兩次。第一批的 PR 補上「同一個 Commons 檔案」的比對（用 `imageSource` 認）：全站 310 篇有封面的文章裡 15 篇因此改成只顯示一次，其中 13 篇是這批新補的，〈豆花〉與〈苗栗縣〉是原本就重複的。
- **譯本（第一批實測後更正）**：封面四欄（`image／imageCredit／imageLicense／imageSource`）是 passthrough 欄位。中文只改 frontmatter 時，正文雜湊不變，譯本可以只抄欄位、不送模型重翻：跟得上中文的譯本用 `bump-source-sha.py --apply --zh-list <清單>` 抄欄位並對齊雜湊；原本就落後的只抄欄位、不動雜湊。**前提是 commit 真的只動到 frontmatter**，見下一條。
- **格式化工具會順手改正文**：pre-commit 對每個 staged 檔跑 `prettier --write`。沒被整理過的文章（多半是從 GitHub 網頁進站的投稿）第一次被碰到時，圖說的 `*斜體*` 會改成 `_斜體_`、腳註之間補空行、帶括號的網址包上角括號。渲染不變，但正文雜湊變了，十二語譯本全部被判成要重翻。第一次 commit 時 33 篇裡有 14 篇、167 份譯本因此過期，已退回重做。全站量過：1,189 篇裡 90 篇會被改到正文，其中 80 篇沒有封面、61 篇在 §5.2 那 133 篇裡。補封面前先量這一項，會動到的先不碰。
- **翻譯產線正在跑**：babel dispatcher 每幾分鐘往 main 寫一次各語言目錄。譯本同步放在每個 PR 的最後一個 commit，rebase 之後用工具重跑，不手解衝突。

## 九、要哲宇決定的事

**格式化會動到正文的 90 篇，怎麼補封面。** 這 90 篇只要有任何 commit 碰到，正文就會被 `prettier` 整理一次，十二語譯本跟著被判成要重翻（一篇十二份，全做是一千多份）。其中 14 篇的封面已經挑好、授權核過，清單在 [`cover-image-health/batch-01-deferred.json`](cover-image-health/batch-01-deferred.json)，包含〈樂生療養院〉〈大腸包小腸〉〈台北車站〉〈燈會〉〈總統府〉〈歌仔戲〉等。

| 選項      | 做法                                                                                                                                                              | 成本與風險                                                                                           |
| --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| A（預設） | 先不碰這 90 篇。等它們下次因為內容更新本來就要重翻時，順便補封面                                                                                                  | 零成本。61 篇有現成圖的文章要等，時間不定                                                            |
| B         | 給 `bump-source-sha.py` 加一條「中文的變動剛好等於格式化工具的輸出」的判定：把舊版正文丟進同一個 `prettier`，結果跟新版逐位元組相同才算，符合就只對齊雜湊、不重翻 | 判準是位元組相等，比現有的「只動標點」判定更嚴。要動翻譯產線的免重翻閘門，建議由產線那一席做並配測試 |
| C         | 一次把這 90 篇格式化完，譯本交給翻譯產線重翻                                                                                                                      | 約 1,080 份譯本進佇列，本機模型要跑好幾天，而且重翻有引入新錯的前例（10/02 那次）                    |

不建議用 `--no-verify` 跳過格式化：那是專案明訂的禁忌，而且下一個碰到這些檔的 commit 還是會把它們整理掉。
