## 一、目標與不做的事

讀者打開 <https://taiwan.md/elections/2026/> 第一眼要能回答四個問題：現在開到哪、我的縣市誰領先、公投走向、哪些說法是真的。

不做的事：

- 不預測、不替任何人宣布當選。「當選」只在中選會標註後顯示，其餘寫「領先」。
- 16:00 前頁面上沒有任何票數或民調（選罷法第 53 條）。
- 不拿媒體自行計票的數字補進中選會的表。口徑不同，引用時另外標明。
- 不評價候選人與政黨。公投只寫票數與兩個門檻，是否通過以中選會公告為準。

## 二、架構：殼只部署一次，數字走資料分支

整站部署一次約十分鐘，而且新的 push 會取消進行中的部署（今天 15:13 就被取消三次）。每 15 分鐘靠重建更新數字不可行，所以拆成兩半：

| 層       | 內容                                        | 位置                                               | 誰可以寫                    |
| -------- | ------------------------------------------- | -------------------------------------------------- | --------------------------- |
| 殼       | 版面、地圖形狀、22 縣市名冊、介面字串       | `main`：`src/components/elections/LiveBoard.astro` | 主 session                  |
| 票數     | 22 縣市首長得票、投開票所進度、公投第 22 案 | `election-live` 分支：`results.json`               | 只有程式（`loop.sh`）       |
| 消息查核 | 目前全貌、最新消息、事實查核，每則附來源    | `election-live` 分支：`feed.json`                  | `election-newsdesk` session |

瀏覽器每兩分鐘從 `raw.githubusercontent.com/frank890417/taiwan-md/election-live/` 讀這兩個檔（跨網域允許、快取五分鐘）。`election-live` 的 push 不觸發部署。本機 clone 在 `~/.taiwanmd-election-live/`。

頁面自己的保險：

- 16:00 前不抓 `results.json`。
- `results.json` 超過 25 分鐘沒更新，頁面亮警示並請讀者看中選會網站。轉錄迴圈停掉時，讀者不會看到一張看似正常的舊表。
- 抓不到資料時顯示「暫時抓不到」加中選會連結。

## 三、票數轉錄（程式，不經 LLM）

```
scripts/tools/election-live/fetch_cec.py       讀中選會計票網站（HTML 片段）
scripts/tools/election-live/publish_results.py 對名冊、算狀態、防倒退、寫 results.json
scripts/tools/election-live/loop.sh            每 180 秒跑一輪並 push 到 election-live
```

- 來源：`https://vote.cec.gov.tw/2026-local/zh-TW/TC/{縣市碼}000000000000.html`（縣市長得票）、`https://vote.cec.gov.tw/2026-ref/zh-TW/F1/00000000000000000.html`（公投）。端點研究：`reports/research/2026-11/election-night-cec-endpoints.md`。
- 16:00 前縣市長端點都是 404，解析器還沒碰過真實檔案。**首次發布前的閘門**：16:0x 用瀏覽器開中選會網站看實際請求，拿一個縣市的腳本輸出跟中選會頁面逐格比對（號次、姓名、票數、當選註記、已完成票所），對上才啟動迴圈。
- 用姓名配對名冊（南投、連江沒有號次）；異體字正規化（温／溫、啓／啟、臺／台）；配不上的寫進 `unmatched`。
- 票數只會往上走。新抓到的比上一版少，當成抓取失敗，保留上一版。
- 心跳：`~/.taiwanmd-election-live/.loop.log` 每輪一行。停止：`touch ~/.taiwanmd-election-live/.stop`。

## 六、每 15 分鐘檢查清單

1. `tail -3 ~/.taiwanmd-election-live/.loop.log`：最新一行在 5 分鐘內、是 `ok`。不是就查 `.fetch.out`，修好重啟。
2. `results.json`：`unmatched` 是空的、`errors` 沒有新種類、`coverage` 逐漸到 22/22。
3. 抽一個縣市，開中選會頁面比對領先者與票數（差距在一輪更新內算正常）。
4. `feed.json` 的 `updatedAt` 在 20 分鐘內；抽一則點來源看是否真有其事。
5. 開正式站看一眼：狀態列、資料時間、沒有警示條。

## 七、每 30 分鐘自我檢查

問自己：讀者現在最想知道的事，頁面第一屏答了嗎？有沒有哪個數字會被誤讀？手機上好不好看？消息有沒有偏向某一方？有沒有該更正的？能改的當場改，殼的改動集中成一次 push（每次 push 都是一次十分鐘部署，並跟 PR session 的合併互相取消）。

## 八、設計決定

- **開票專區用夜色版面**：選舉夜的現場感，政黨色在深底上最好辨識。淺色與深色主題下都一樣。
- **用政黨色**：`elections.css` 原本規定圖表不用政黨色（那是為了候選人人數圖）。開票結果需要辨識政黨，這個元件是明確的例外；每個色塊旁都有文字，顏色不是唯一資訊。
- **專頁色票**：從偏黃的米色加鐵鏽棕，換成紙白、墨黑、圈選章朱紅（跟各政黨代表色都不同）。只改 token，五個選舉頁一起變。
- **舊設計報告寫「不做即時開票」**（`reports/design-elections-2026-upgrade-2026-11-17.md`）：哲宇今天的指示改了這個決定。
- **地圖投影程式跟 `CountyMap.astro` 重複一份**：時間取捨，選後抽成共用工具。

## 十、迭代紀錄

### 16:01 開票啟動

中選會端點 16:00 上線，22 縣市與公投都抓得到，名冊配對零落差。票所進度寫在頁首「已送投票所數/總投票所數: 0/1790」，原本的解析抓不到，已修。轉錄迴圈 16:02 啟動，每 150 秒一輪。逐格比對還沒做：16:16 為止中選會所有縣市都是 0 票 0 所。

### 16:16 第一輪自我檢查

看到的：等第一批票數的這段時間，第一屏是一條空的灰色條加「還沒有票數」，看不出資料其實在更新。中選會連結的箭頭出現兩次。導言寫「每 15 分鐘轉錄」，實際是每兩三分鐘。手機上地圖排在後面，要找自己的縣市得滑很久。

改了的：等待中也顯示資料時間與「已回報 0 / 18,248 所」；沒有票數時收起空色條；加一排「跳到你的縣市」，有票數後每顆會帶領先政黨的顏色；箭頭去重；十三語導言改成每 3 分鐘。

下一輪想看的：第一批票數進來後，卡片的排序與「領先」標示在只開一兩所時會不會誤導（考慮在回報比例很低時加註）；公投區塊在手機上的高度；頁面下半部舊的「今天投票」狀態列在開票後是否該收掉。

### 16:46 第二輪自我檢查

看到的：16:42 第一批票數進來（臺南市 1／1,563 所），跟中選會逐格一致（2／43／72 票），首次發布的比對閘門算通過。但正式站第一屏寫成「民進黨 1：臺南市」，一條綠色色塊，依據只有一個投開票所的 117 票。公投也一樣，110 票就顯示「門檻一目前達到」。數字都對，讀法會錯。

改了的：回報不到 5% 投開票所的縣市標成「開票初期」，卡片虛線、地圖淡色，不計入各黨領先數（色條另開一段斜紋）；公投兩個門檻在 5% 以下也只寫「開票初期」。已回報比例小於 1% 時多顯示一位小數，不再出現「0.0%」。值班檢查寫成 `scripts/tools/election-live/check.py`。

下一輪想看的：5% 這條線在大縣市與小縣市是否都合理（連江 12 所，開 1 所就 8%）；有十幾個縣市都有票數後，第一屏要不要加一句話的現況摘要（消息台的「目前全貌」開始有內容後看擺放位置）。

### 17:16 第三輪自我檢查，加上哲宇的回饋「線上更新太慢」

看到的：縣市快速鍵在「開票初期」仍是飽和的政黨色，跟上面「不計入領先數」的說法打架；狀態列只有數字，看不出全國開到哪。

哲宇說線上更新太慢。量了三段延遲：轉錄迴圈每 150 秒一輪；資料檔放在 raw.githubusercontent.com，分支網址固定快取五分鐘，實測加查詢字串也繞不過（任意新字串都回快取命中）；瀏覽器每兩分鐘抓一次。最壞情況落後中選會將近十分鐘。中選會網站不允許跨網域，瀏覽器不能直接讀。

改了的（只為今晚）：

- 瀏覽器先問 GitHub API 資料分支最新的提交碼（快取一分鐘、允許跨網域），再用提交碼網址取檔；提交碼網址的內容不變，沒有舊快取。API 匿名額度每個 IP 每小時 60 次，頁面最多每 70 秒問一次，問不到就退回原本的分支網址。
- 轉錄迴圈改成約每 55 秒一輪（中選會自己是每分鐘更新）；瀏覽器每 75 秒抓一次。
- 預期落後從最壞十分鐘降到兩三分鐘。
- 縣市快速鍵在開票初期用淡色；狀態列加全國開票進度條；開票初期的卡片不顯示「領先幾票」。

沒選的路：在 Cloudflare 開 Worker 加 KV 由迴圈直接推檔，延遲可以更低，但要在哲宇的帳號上新增部署、綁路由，今晚只用一次不划算；用 GitHub API 的做法不需要任何新設施。

下一輪想看的：共用同一個對外 IP 的讀者（公司、學校、電信商 NAT）會不會一起把 API 額度用完，退回舊路徑時延遲是否可接受；選後把這段取檔邏輯拿掉。

### 17:25 哲宇貼 Yahoo 開票頁，問能不能用 socket

查了 Yahoo 那頁：沒有 websocket。它是一篇每十分鐘手動更新的直播文，加上 22 張 Datawrapper 圖表（每張一個縣市，定時重新發布，資料檔 `dataset.csv` 公開）。它快的原因在資料來源：用的是媒體自行計票，17:23 臺北市已 36 萬票對 31 萬票，同一時間中選會的臺北市只回報 4／1,790 所。所以慢的不是傳輸方式，是中選會官方數字本來就比媒體晚一到兩小時；socket 幫不上忙。

決定（改掉 §一「不拿媒體數字」的原則，範圍限今晚）：另外轉錄一份媒體計票，跟中選會數字分開放。

- `scripts/tools/election-live/fetch_media.py`：讀 Yahoo 的 22 張圖表資料檔，用候選人姓名對回名冊決定縣市，寫 `media.json`。一樣只有程式寫。
- 頁面最上面多一塊虛線框「媒體計票：目前領先的縣市數」，標「非官方」、標來源與時間，並說明為什麼兩個數字差很多；下面才是「中選會官方計票」。每張縣市卡片底下多一列媒體計票（前兩名）。
- 不採用媒體資料裡的「當選」標記（那是候選人自行宣布）。地圖、公投、「當選」仍只看中選會。
- 媒體計票超過 40 分鐘沒更新就整塊不顯示。

風險：媒體計票可能有誤差，也可能灌水；來源只有 Yahoo 一家（它沒有標明是哪家電視台的數字）。頁面寫明非官方並連回來源。

### 17:46 第四輪自我檢查

看到的：含媒體計票的版本已上線，17:46 的資料在 17:46:56 就顯示（瀏覽器走的是提交碼網址，快取那段確實消掉了）。第一屏現在回答得了「哪一黨領先幾個縣市」，但回答不了「我的縣市誰領先」，要往下滑到卡片。地圖還在用中選會數字，而 22 個縣市裡 19 個中選會還在開票初期或沒資料，整張圖是淡的。17:27 轉錄迴圈推送失敗一次（跟消息台搶同一個分支），下一輪自己補上。

改了的：媒體計票區塊加一排 22 縣市一覽（縣市、領先者、領先幾個百分點，差距 5 點內用虛線框），每格連到該縣市卡片。地圖在中選會開票初期或沒資料的縣市改用媒體計票上色，用虛線邊，圖說標「媒體計票・非官方」；中選會回報過 5% 的縣市照舊用官方數字。迴圈推送前再對齊一次、失敗重試。

下一輪想看的：中選會回報比例上來後，媒體與官方兩塊的主從要不要對調（官方過半數縣市脫離開票初期時，把官方移回最上面）；媒體計票一覽在手機上是兩欄，22 格偏長，看要不要只列六都加膠著的。

### 18:16 第五輪自我檢查（先請顧問審過一次）

顧問指出三個自檢量不到的洞，這輪都補了：

1. 媒體計票的過期保險量錯欄位。原本看我們自己的抓取時間，而我們每分鐘都抓，Yahoo 停更時那個時間照樣是新的，「40 分鐘沒更新就不顯示」其實不會觸發。改成看來源每張圖表自己的更新時間：22 張裡最新的一張也超過 40 分鐘，整個來源不用；單一縣市超過 120 分鐘不用（小縣市媒體很早計完就不再更新，所以單張放寬）。
