## 0. 方法與查證限制（先看這段）

1. **data.gov.tw 的數字不是印象，是實測**。首頁與統計頁是 JS 渲染（WebFetch 只拿到「無資料」空殼），所以我用兩條路交叉：
   - 平臺前端自己呼叫的 JSON 端點 `POST https://data.gov.tw/api/front/dataset/list`（回傳 `search_count`）。
   - 平臺「全部資料集清單下載」`https://data.gov.tw/api/front/dataset/export?format=csv`（68,731,270 bytes，52,556 列），自己用 Python 統計。
     兩者都是 **52,556**，吻合。這個端點是網站前端使用的，**不是官方文件化的對外 API**（官方指引 `https://data.gov.tw/instruction` 的 API v1/v2 是給機關推送詮釋資料用的 M2M 介面）。
2. **WebFetch 對不少台灣政府站失效**：`www.stat.gov.tw` 回「unable to verify the first certificate」；`www.ndc.gov.tw`、`pop-proj.ndc.gov.tw`、`index.ndc.gov.tw` 回 403（Cloudflare 擋腳本）；`www.moea.gov.tw` 對腳本也回 403。我改用 `curl -k` 取頁面文字（標「✅ curl 打開」），國發會／經濟部統計處內容因此只能走 🔍 或透過 data.gov.tw 目錄間接驗證。
3. **WebSearch 額度在本輪用完**（每輪上限 200 次、各分身共用）。TDX 規模、ODIN 台灣是否納入、經濟部統計處／勞動部查詢網細節因此留 ❓。需要補的話請下一輪再開。
4. 中文頁面我都要求逐字擷取；WebFetch 的回覆若已被模型摘要過，我只引用它回傳的引號內文字。
5. 沒有查到的就寫「查不到」，不用記憶補空。

## 1. 總覽：台灣官方資料生態長什麼樣

**一句話：台灣的官方資料「量很大、入口很多、品質不齊」，而且沒有一個地方替公眾把它整理成『找得到、讀得懂、可比較』的樣子。**

- **一個國家級目錄＋幾十個機關自建站。** 政府資料開放平臺 data.gov.tw（數位發展部營運）是目錄，**共 52,556 個資料集、約 799 個提供機關名稱**（✅，見 §3.1）。但實際檔案常放在機關自己的站（臺中 newdatacenter.taichung.gov.tw 一站就被 18,818 個下載連結指向；勞動部 apiservice.mol.gov.tw 16,210；臺南 soa／data.tainan 兩站共約 22,000；財政部 fia.gov.tw 8,258；司法院 6,990……，✅ 自目錄統計）。
- **數量被「切片」撐大。** 把標題裡的民國年份抹掉再去重，52,556 筆只剩 **43,527** 個不同標題（✅）；例如新北「XXX年度新北市總預算歲入歲出簡明比較分析表」同一份表有 16 個年度各一筆。這是歷史習慣（一年一個資料集），對使用者就是要自己拼時間序列。
- **官方統計另成一個體系。** 行政院主計總處的「中華民國統計資訊網」（stat.gov.tw）、總體統計資料庫、縣市重要統計指標、三大普查平臺、薪情平臺，加上各部會統計處（內政、教育、衛福、經濟、勞動、財政、環境、農業、法務）各自做查詢系統與視覺化，彼此不互通。主計總處自己的「統計視覺化」頁面就是一張「各部會互動圖表入口清單」（✅ https://www.stat.gov.tw/News_Photo2.aspx?n=3776&sms=11154），等於承認這件事需要人工導覽。
- **特定領域做得很好，而且是「即時 API」型。** 交通（TDX）、證券（TWSE／TPEx OpenAPI）、氣象（CWA）、水利（WRA）、環境（MOENV）、台電、立法院、選舉資料庫。這些領域有穩定結構、有開發者社群，也是民間 App 最常用的來源。
- **國際評比上有歷史高光，之後就看不到了。** Global Open Data Index 2015 與 2016 連兩屆世界第一（✅ 2016 版 90%、領先澳洲與英國的 79%）；之後 Index 停止營運；Open Data Barometer 的台灣頁面顯示無資料；Global Data Barometer 2022 第一版有台灣報告，總分 51（全球平均 33）（§5）。
- **授權單純是強項。** 52,556 筆裡 **52,514 筆（99.92%）** 用「政府資料開放授權條款－第1版」，條款本身寫明與 CC BY 4.0 相容（✅，§6）。
- **體驗上的主要痛點是「工程摩擦」**：Big5 編碼、民國年、日期混用、API 要金鑰或有時段限制、同一概念散在 50 多個網站、PDF 當資料、站點憑證鏈不完整、爬蟲被 WAF 擋（§7）。

## 6. 授權

**政府資料開放授權條款－第1版**（中華民國 104 年 7 月 27 日訂定，✅ https://data.gov.tw/license 逐字）：

- 二(一)：「各機關所提供之開放資料，授權使用者不限目的、時間及地域、非專屬、不可撤回、免授權金進行利用，利用之方式包括重製、散布、公開傳輸、公開播送、公開口述、公開上映、公開演出、編輯、改作…」
- 三(二)：使用者「應以符合附件所示『顯名聲明』要求之方式，明確標示原資料提供機關之相關聲明；未盡顯名標示義務者，視為自始未取得開放資料之授權。」
- 四(二)：「本條款與『創用CC授權 姓名標示 4.0 國際版本』相容，使用者依本條款利用開放資料，如後續以『創用CC授權 姓名標示 4.0 國際版本』規定之方式利用，視為符合本條款之規定。」
- 五：機關在「情事變更」「不符公共利益」或「可能侵害第三人權益」時可停止提供，使用者不得請求賠償（頁面摘要，非逐字）。
- 六(二)：除法令另有規定外，提供機關不負損害賠償責任（摘要）。七：以中華民國法律為準據法。

**對 Taiwan.md 的實務結論**

1. 引用、整理、再發布（含商業）都可，**必須標示「顯名聲明」**；未標示＝視為自始未獲授權（風險較 CC BY 更嚴苛）。
2. 單向相容：依條款取得的資料，可「以 CC BY 4.0 的方式」再利用；反過來說，策展中樞對自己的衍生整理若要採 CC BY 4.0，這是合法的。
3. 「不可撤回」與第五條「機關得停止提供」並存，且疾管署 234 集下架是實例（§3.7）。**策展中樞要保存「取得日期＋當時版本＋來源 URL」**。
4. 目錄中的例外：CC BY 4.0（16）、CC0（15）、CC BY-SA 4.0（8）、OFL-1.1（3）共 42 筆；其中 BY-SA 必須逐筆處理，不能與第1版資料混成同一授權的衍生資料。
5. 授權不等於可批量抓取：台電、中選會等站點的服務條款或爬蟲防護另有規定，大量抓取前要逐站檢查。

## 7. 痛點（附實例）

**P1 分散在幾十個平台、同概念散在多處**

- 主計總處統計資訊網的「統計視覺化」頁人工列出 11 個部會的互動圖表入口（§4）。

- 5,348 筆（10.2%）無常見結構化格式；PDF 唯一格式 1,187 筆。
- 更新頻率標籤同義異寫（每日／每1日／每1天）。
- 例：交通部運輸研究所單一機關有 311 筆 PDF 唯一格式資料。

**P4 Big5 編碼 CSV**

- 目錄有 5,313 筆（10.1%）含 BIG5。實例（✅ 我下載後以 iconv big5→utf-8 可讀）：臺北市政府警察局財產統計表 https://data.taipei/api/dataset/23a8701b-9ee8-4c49-a362-2b12f14a30bc/resource/449126fc-8306-432a-9c40-479f803cb2e7/download，首列 `年度,財產類別,上期結轉,…`，資料列 `114,土地筆數,246,…`。中選會「政府資料開放行動方案」CSV（id 120829）、央行「中央銀行雙語詞彙」（id 170729）也標 BIG5——**連制定開放資料政策的機關自己也在發 Big5**。

**P5 民國紀年／日期混用**

- 29.3%（15,392 筆）資料集標題含民國年（如「109年度中央政府總決算…」「114年度桃園市各區土地公告現值」）；14.8% 標題直接以民國年開頭。
- 實例（✅）：TWSE OpenAPI 同一回應中 `"出表日期":"1151022"` 是民國、`"成立日期":"19501229"` 是西元；臺北市 CSV 的年度欄是 `114`。

**P6 死連結／不可存取**

- 抽樣方法：從 data.gov.tw 清單隨機抽 300 筆資料集（固定亂數種子 20261023），各取其中一個下載 URL，發 GET（Range 0–1023，User-Agent 為一般瀏覽器）。結果：**257 筆回 200/206，43 筆失敗**（403 共 12、503 共 5、502 共 3、連線逾時／重置 23）。
- **這不能直接當成「死連結率 14%」**：403 多是機關 WAF 擋腳本（經濟部、主計總處、雲林縣、中小企業署）；新北 data.ntpc.gov.tw 的 `csv/file` 端點回 401 未授權。真正「已不存在」需要逐筆瀏覽器確認。
- 另外確定的個案（✅ 2026-10-23 實測）：基隆市稅務局「108年印花稅徵收」https://www.kltb.gov.tw/wSite/public/Attachment/010/f1690527651043.csv 回 **HTTP 428**，回傳是 HTML 而非 CSV；疾管署 234 集整批下架（§3.7）；司法院 API 每天只開 6 小時（§3.4）。
- 憑證鏈：若以預設 TLS 驗證，同一批 300 筆中有 136 筆連線失敗（Python 預設憑證庫）；改成不驗證後降到 22。至少 `www.stat.gov.tw` 與 `www.dgbas.gov.tw` 確認是中繼憑證缺漏（`openssl s_client` Verify return code: 21，✅）。其餘失敗的根因（含 TWCA 根憑證是否在本機信任庫）❓ 未逐一確認，本機環境因素無法排除。

**P7 沒有穩定 API**

- 氣象署：無 key 回 401（✅）；環境部：無 key 回「api_key 不存在」，匿名 300 次/日（✅）；新北：401（✅）；司法院：Token＋0–6 時（✅）；立法院、TDX（部分端點）、TWSE／TPEx、台電 JSON：免 key（✅）。
- 全國目錄本身沒有官方文件化的檢索 API（前端用的 `/api/front/dataset/list` 只接受 POST、參數名稱需從前端反推，如 `page_num`、`page_limit`、`sort=resource_download_times_desc`；不保證穩定）。
- 官方「政府資料開放平臺」指引中的 API v1/v2 是機關新增／修改／下架詮釋資料用（✅ 指引頁錨點 postdata／putdata／deletedata）。

**P8 欄位定義不清**

- 目錄的「主要欄位說明」幾乎都有填（僅 228 筆空），但那多是欄位名稱列表，樣本中欄位 `desc` 空字串（nid 178955）；31.3% 資料集描述不足 20 字。TWSE 所有數值型欄位為字串，欄位單位（千股？元？）需自行查規格。

**P9 只給 PDF／月報 PDF**

- 勞動部勞動統計月報為 PDF（🔍 statdb.mol.gov.tw/html/mon/…pdf）；運輸研究所 311 筆 PDF；國家海洋研究院 148 筆。

**P10 網站改版與網址漂移**

- 內政統計查詢網舊址 `stmain.jsp?sys=100` 回 404，新址為 `webMain.aspx?sys=100&funid=defjsp`（✅）；SEGIS 轉為「社會經濟資料服務平台」`STATCloud`（✅）；國家文化記憶庫 `memory.culture.tw` 網域不解析、改至 `tcmb.culture.tw`（✅ tcmb 可開；改址時間 🔍）；`mops.twse.com.tw/mops/web/index` 回錯誤頁，現行 `mopsov.twse.com.tw`（✅）；`data.nhi.gov.tw` 不解析、實際在 `info.nhi.gov.tw`（✅）。

**P11 站點對機器不友善（WAF／SPA）**

- 國發會三個網域、經濟部統計處對腳本回 403（✅）；data.gov.tw、TDX、TGOS、司法院開放平台、立法院之外的多數新站是 SPA，WebFetch 類工具只能拿到空殼（✅ data.gov.tw 首頁「無資料」、司法院「請啟用 JavaScript」）。

## 8. 策展中樞可以補的十個缺口（可落地為頁面功能）

> 排序＝價值×可行性。每項標：它補的痛點／要做什麼頁面功能／資料來源／工作量（S 一週內，M 兩到四週，L 一個月以上）。

1. **「全國官方資料一張總索引」：把 data.gov.tw 52,556 筆做成可搜尋、可下載的乾淨索引**
   - 補：P1、P2、P3。做法：每日抓清單下載（CSV）→ 正規化機關名稱（補縣市前綴）、更新頻率同義詞、格式、編碼、民國年 → 輸出 Parquet/CSV/JSON 與一個站內搜尋頁；欄位含「是否 UTF-8」「含 CSV？」「PDF only？」「最近變更日」。工作量：M。資料：`https://data.gov.tw/api/front/dataset/export?format=csv`（✅ 可用，未文件化，需定期驗證）。

2. **「主題整合頁」：把散在多個平台的同概念資料集整理成一份主題包**（人口、薪資、電力、房價、交通事故、選舉、空品、物價、出生）
   - 補：P1。例：人口 1,126 筆／73 機關／56 網域 → 策展出「人口」十幾張核心表（戶政司月報、主計總處縣市指標、普查、國發會推估、內政部 SEGIS），每張標來源、口徑差異、最新期。工作量：M（每主題 S）。

3. **「資料入口地圖」：給非工程師的『我想找 X，去哪裡』決策頁**
   - 補：P1。以本報告 §2 為底，加上『免 key／要 key／要登入／僅 PDF／被 WAF 擋』標籤與直連連結。工作量：S。

4. **「官方 API 體檢表」：每個 API 的認證、配額、時段、欄位範例、是否民國年**
   - 補：P7、P5。涵蓋 TWSE、TPEx、TDX、CWA、MOENV、WRA、LY、司法院、台電、MOA。每格含可複製的 `curl` 範例與實測回應（如 TWSE 的 `1151022`）。工作量：M。

5. **「清洗好的核心時間序列」：把主計總處／央行／財政部重要指標做成 UTF-8、西元日期、單一長表的下載包**
   - 補：P4、P5、P8。以主計總處 12 項重要經社指標為起點（失業率、CPI、經濟成長率、薪資、出口入…），附『原始來源 URL＋取得時間＋授權顯名聲明』。工作量：M。注意授權顯名要求（§6）。

6. **「民國↔西元、Big5↔UTF-8 轉換說明＋函式庫範例」教學頁**
   - 補：P4、P5。以 data.taipei 警察局財產表、TWSE `t187ap03_L` 為實例，提供 Python／R／JS 三種範本與常見陷阱（TWSE 數值是字串、同回應民國西元混用）。工作量：S。

7. **「這個連結還活著嗎」資料集健康監測**
   - 補：P6。對索引中的下載連結定期 HEAD/Range 檢查，記錄狀態碼、回應是否為 HTML 偽裝 CSV（如基隆 428 實例）、是否 TLS 鏈錯誤，並顯示『上次成功取得日』。要區分 WAF 403 與真死連結（§7 P6）。工作量：M-L。

8. **「資料下架與異動時間軸」＋存證快照**
   - 補：P6 + 授權第五條風險。每日 diff 清單（`changed/list` 與清單下載），追蹤上下架；疾管署 234 集下架（預計 115 年 11 月底回歸）就是頁面第一筆。對高價值小檔案保留帶雜湊與取得日期的快照。工作量：M。

9. **「國際評比與台灣位置」頁：Global Open Data Index 2015/2016 第一、GDB 2022 的 51 分與 Use and Impact 23 分**
   - 補：使用與影響缺口（§5）。放評分、方法差異、各分項（政府支出 0%、水質 85%）、與 OECD OURdata 不涵蓋的說明。誠實寫出 ODIN 台灣狀態『查不到』。工作量：S。可與 R3、R4 報告交叉。

10. **「看得懂的官方儀表板收藏館」：把各部會做得好的互動圖表（普查、薪情、教育統計、臺北城市儀表板）策展成導覽，並標示『資料可下載與否、授權、更新日』**
    - 補：視覺化空位（§4）。每項附『我們想補的圖』提示（跨部會總覽、縣市比較）。同時可與 Taiwan.md 文章連結（知識＋數據的差異化）。工作量：S–M。

**不建議做**：複製各機關資料（授權顯名＋維護成本＋下架風險）、逐站爬 WAF 站點（國發會、經濟部），應改走 data.gov.tw 目錄中已公開的檔案連結。
