## 1. URL 組成規則

### 1.1 規則本體【已實測：簡歷檔與公投檔都照此規則得到 200】

來源：`index_pc2.js` 的 `computeLink`（行為）與 `tree-compiled.2026-*.min.json`（參數）。

```
{頁面目錄}/{prefix}/{c}{y}{d}{v}{b}.html
頁面目錄 = https://vote.cec.gov.tw/2026-local/zh-TW/   （公投為 2026-ref/zh-TW/）
c = 5 碼縣市碼（預設 00000）  y = 2 碼（預設 00）  d = 3 碼（預設 000）
v = 3 碼（預設 000）          b = 4 碼（預設 0000）   共 17 碼
```

- 前端把 link 當相對路徑，直接放進 `<vote-frame src>`，用 `fetch(src, {cache:"no-store"})` 取回 HTML 片段，塞進頁面。
- 資料檔是 **HTML 片段（內含 `<table class="tablesaw">`），不是 JSON**。
- 計票階段（stage=COUNT）時 vote-frame 每 60 秒（`refreshIntervalMs=6e4`）重抓一次。腳本輪詢頻率建議 >= 60 秒。
- 唯一的 JSON 是 `{link去掉.html}_PS.json`（`.replace(".html","_PS.json")`）：只在 `final` 階段、投開票所層級（tag D）才出現，內容是「投開票所號碼陣列」（`Array of ballot numbers`，補成 4 碼）。這不是開票資料。
- 服務端是 nginx 後面的 HiNetCDN；不存在的檔回 `404`（約 146 到 548 bytes 的 nginx 404 頁）。`/2026-local/home/zh-TW/` 回 403。

### 1.4 投開票所完成數（已開票所數 / 總票所數）【推導未實測，最大不確定點】

- tree 與 JS 裡 **沒有任何獨立的「進度」端點**；沒有 `progress` / `status` 之類的檔。
- 最可能放在 `TC/` 頁面本身（表頭或 subtitle），或 `SC/`（選舉概況，count 階段 traversal 到縣市為止）。**開票前這兩個都 404，無法確認欄位**。
- 腳本 `find_progress()` 以兩招猜：表頭含「票所」且含「已/完成/送」或「應/總」；或全文正則 `投開票所…12/2,000`。猜不到時 `reported/total = null`，不報錯。

## 3. 資料檔格式

### 3.1 候選人簡歷 CC【已實測】

`<div id="vote-table-header">`（標題 `<b>臺北市 直轄市長選舉 候選人簡歷</b>`）＋ 一個 `<table class="tablesaw">`，欄位：號次、姓名、性別、推薦之政黨。無「資料時間」頁尾。

### 3.2 候選人得票 TC【推導未實測】

預期是同樣的 header + `tablesaw` 表 + `vote-table-footer`（`資料時間: MM/DD HH:MM`，公投檔實測有）。預期欄位：號次、姓名、推薦之政黨、得票數、得票率%、當選註記，可能還有進度。腳本以欄位名關鍵字（`姓名`、`得票數`、`得票率`、`當選`/`註記`、`政黨`）定位，順序不敏感。當選註記的真實符號未知（腳本接受任何非空且非 `-` 的值）。已用合成 HTML 做過離線解析測試，真實檔未測。

### 3.3 公投 F1【已實測（全 0）】

四個一列式表：

1. 同意票數 / 不同意票數
2. 有效票數 / 無效票數 / 投票數
3. 已完成投票所投票權人數 / 已完成投票所投票率%
4. 投票權人總數 / 有效同意票數對投票權人總數百分比%
   頁尾：`資料時間: 11/28 00:10`。數字帶千分位逗號，百分比帶 `%` 前的數字（如 `0.00`）。
